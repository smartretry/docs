---
title: Initialize recurring
description: Create a new recurring billing agreement and process the first payment in the series.
openapi: "/api-reference/openapi.json POST /v1/payments/recurring/init/{terminal_friendly_id}"
---

Initializing recurring billing creates a series and submits its first transaction for processing.
Save the returned `recurring_id` for later recurring and future-transaction operations.

## Payment instrument

`payment_instrument` is required — unlike sale and pre-authorization, a hosted-page collection does
not make it optional here, since the new recurring series and its stored credential are created in
the same step. It accepts exactly one credential source: raw card details, a SmartRetry `token`, or a
processor `provider_token`. See [Payment methods](/integration/payment-methods) for the full field
reference.

Provide either `payer` or `payer_fingerprint` — not both. `payer_fingerprint` is a pre-computed
identifier from an earlier transaction for the same payer.

## Retry a previous initialization

Use this same endpoint to create a new retry attempt. In the request body, provide
`retry.originating_id` for the previous SmartRetry recurring initialization transaction.

<Note>
  A retry request creates a new attempt. To safely replay the exact same request after an ambiguous
  failure, reuse its `Idempotency-Key`. See [Idempotency](/api-reference/idempotency).
</Note>
